 SECTION 1 | WHAT ARE ACTIVITIES?
-------------------------------------------------------------------------------

  Activities are named experiences tied to a CITY or HOTEL, e.g.
    - Tea Plantation Tour (Munnar)
    - Kathakali Dance Performance (Cochin)
    - Houseboat Cruise (Alleppey)
    - Eravikulam National Park Safari (Munnar)
    - Chinese Fishing Nets Walk (Fort Kochi)

  Each activity record contains:
    Field            | Description
    ─────────────────────────────────────────────────────────────────────
    name             | Display name of the activity
    description      | Short detail / what is included
    price            | Per-person cost (INR)
    category         | sightseeing / adventure / cultural / leisure
    duration         | e.g. "2-3 hours" or "Half Day"
    city             | Ref -> City._id  (required)
    hotel            | Ref -> Hotel._id (optional, hotel-specific activity)
    images           | [ { url, publicId, caption } ]
    isHighlight      | Boolean — featured in package highlights?
    createdBy        | Ref -> User._id

 SECTION 4 | DATA MODEL — Activity.js (Mongoose Schema)
-------------------------------------------------------------------------------

  FILE: src/models/Activity.js

  const ActivitySchema = new mongoose.Schema({
    name:        { type: String, required: true, trim: true, maxlength: 150 },
    description: { type: String, trim: true, default: "" },
    category:    {
                   type: String,
                   enum: ["sightseeing","adventure","cultural","leisure"],
                   default: "sightseeing"
                 },
    duration:    { type: String, trim: true, default: "" },
    price:       { type: Number, min: 0, default: 0 },
    city:        { type: ObjectId, ref: "City", required: true },
    hotel:       { type: ObjectId, ref: "Hotel", default: null },
    isHighlight: { type: Boolean, default: false },
    images:      [ImageSchema],
    createdBy:   { type: ObjectId, ref: "User", required: true },
  }, { timestamps: true });

  Indexes:
    { city: 1, name: 1 }   <- fast lookup by city
    { category: 1 }         <- filter by category

 SECTION 5 | API ROUTES
-------------------------------------------------------------------------------

  GET    /api/activities
    Query params: ?city=<cityId>  ?category=<cat>  ?search=<q>
    Returns: { activities: [...] }
    Auth: any logged-in user

  POST   /api/activities
    Body: { name, description, category, duration, price, city, hotel, isHighlight }
    Returns: { activity: { ...saved } }
    Auth: admin / superuser only

  GET    /api/activities/[id]
    Returns: { activity: { ...full detail } }
    Auth: any logged-in user

  PUT    /api/activities/[id]
    Body: (any updatable field)
    Auth: admin / superuser only

  DELETE /api/activities/[id]
    Auth: admin / superuser only

 SECTION 13 | OPEN QUESTIONS / DECISIONS NEEDED
-------------------------------------------------------------------------------

  1. PRICING IN PACKAGE:
     Should selected activity prices be:
     (a) Auto-added to package total price? (recommended for accuracy)
     (b) Informational only — displayed but not summed into package cost?

  2. HOTEL vs CITY ACTIVITIES:
     Hotel model already has activities[] (name + price) embedded.
     Should the new Activity component REPLACE that embedded list or
     COEXIST with it?
     Recommendation: COEXIST — hotel-level activities are quick overrides,
     city-level activities are the master library.

  3. ACTIVITY IN ITINERARY:
     When user types an activity name in the Itinerary builder (e.g. Day 1
     "Cheeyappara Waterfalls Visit"), should it auto-link to an Activity
     document from the DB? Or remain a free-text entry?

  4. PERMISSIONS:
     Members (non-admin) — can they VIEW activities?
     Recommendation: YES (read-only). Only admin/superuser can CREATE / EDIT / DELETE.
